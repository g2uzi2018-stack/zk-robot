# TI5 T170C 独立实机测试菜单

`ti5_zero_home` 是独立的硬件在环测试程序，不修改也不替代
`ti5_full_check`。程序启动后提供三个动作：

1. 头部和双臂 17 轴回到 CAN 电机角 `0 rad` 并保持；
2. 双臂经过两个中间点缓慢下放，在第二中间点发送 `0x02 STOP`；
3. 头部和双臂 17 轴在刚读取的当前位置建立 CSP HOLD。

固定排除 `waist_yaw`、`Fold_P1/P2/P3/R` 和左右傲意手。菜单 2 也不会改变头部状态。

## 重要语义

菜单 2 先读取本次起点 `q0`，再以只读采样得到的完整自然下垂位置 `q_down` 为参考，计算：

- 第一中间点：`q0 + (q_down - q0) / 3`；
- 第二中间点：`q0 + 2 × (q_down - q0) / 3`。

程序用五次曲线依次运动到两个中间点，峰值速度不超过 `0.10 rad/s`；第一中间点保持 `0.5 s`，第二中间点保持并验证 `1 s`。到达第二中间点后程序继续保持，不会立刻 STOP；操作者必须先可靠托稳双臂并再次输入 `y`，程序才向双臂 14 轴发送 `0x02 STOP`。完整 `q_down` 永远不作为 CSP 命令目标。

如果启动菜单 2 时双臂 14 轴已经全部是 `mode=0`，程序不会重新建立 CSP，也不会尝试缓降，只重复发送 STOP 并核验状态。若 14 轴不是全部 `mode=8` 或全部 `mode=0`，程序会因模式混杂而拒绝动作。

菜单 2 的 `0x02 STOP` 只保证驱动器进入运行模式 `mode=0`，不能据此承诺去使能、释放转矩、释放抱闸或一定自然下垂。第二中间点之后仍有约 1/3 的剩余行程可能由重力完成；执行前和执行过程中必须可靠托住双臂，并清空下方和夹点。物理急停始终优先于软件菜单。

完整下垂位置可能略微越过驱动器 `0x1A/0x1B` 目标范围。同位置 `0x44(q0)` 在范围外会被忽略；菜单 1 不会反复发送这个无效目标，而是仅在当前位置属于上述已记录自然下垂走廊、超出驱动器范围不超过 `0.12 rad` 时，先命令到驱动器边界内侧 4 个编码器计数的接管点。这样既保证目标落在驱动器可接受范围内，也不再额外增加 `0.005 rad` 的首次位移。确认后、实际发送控制命令前还会重新读取一次位置；如果确认期间位置变化超过 `0.01 rad`，本次操作会取消并要求重新执行。接管速度使用每帧 CAN 反馈自身的接收时刻，以至少 `50 ms` 的连续反馈窗口统计累计位移，并扣除 2 个编码器计数的分辨率误差；这会排除单帧取整尖峰，但持续超速仍会触发原有 `0.20 rad/s` 上限。反馈包络、`mode=8`、`fault=0` 和最终位置容差也必须同时满足，之后才进入正常五次曲线回零。

2026-08-23 实机确认：右肩从 `1.502966 rad（86.114°）` 接管到 `1.478527 rad（84.713°）`，100/100 帧反馈正常，最大实际位移 `0.023633 rad`、最大观测速度 `0.088683 rad/s`；随后 17 轴以 `0.15 rad/s` 峰值完成同步回零，全部进入 `0 ±0.012 rad` 并保持。全程没有发送 `0x01`、参数写入、Flash 或抱闸控制命令。

## 菜单 1 和菜单 3

菜单 1 和菜单 3 在发送 `0x44` 前逐轴检查当前位置、mode、fault、`safety.yaml` 电机角限位和驱动器 `0x1A/0x1B`。菜单 3 仍要求当前位置处于正常限位内。菜单 1 对已记录的肩横滚自然下垂走廊允许受限边界接管；其他姿态不放宽。

菜单 1 还有以下约束：

- 回零目标使用 `motor_rad=0`，不使用 `kinematics.yaml` 模型偏置；
- 零点必须在软件限位和驱动器目标位置范围内保留至少 `0.02 rad` 余量；
- 普通关节距离零点不得超过 `0.50 rad`；肩横滚仅在已记录的恢复走廊内允许到 `1.62 rad`；
- 使用五次曲线同步回零，轨迹峰值速度不超过 `0.15 rad/s`；
- 最终 17 轴都必须进入目标 `±0.012 rad`。

菜单 3 不规划位移，但切换或重新建立 CSP HOLD 时仍可能产生小幅纠偏。

## 编译与无动作检查

```bash
cd ~/workspace/zk_robot
cmake -S . -B build
cmake --build build --target ti5_zero_home -j2
./build/tools/ti5_zero_home --dry-run
```

`--dry-run` 只打印范围和菜单，不打开 CAN，也不发送任何帧。

## 实机执行

先关闭 Ti5Control、`ti5_full_check`、`joint_manager`、`ti5_follow_arm` 和其他 CAN 控制程序，然后执行：

```bash
cd ~/workspace/zk_robot
sudo env ZK_ROBOT_CONFIRM_TI5_TEST=YES \
  ./build/tools/ti5_zero_home
```

程序显示菜单后输入 `1`、`2` 或 `3`。完成只读预检后会要求 `y` 或 `Y` 现场确认。菜单 2 到达第二中间点后还会再次等待托稳确认；第二次输入 `y` 前不会发送 STOP。

如果本体四路 CAN 已经正确处于 UP/1 Mbps，且当前用户具备 SocketCAN 访问权限，也可以使用：

```bash
env ZK_ROBOT_CONFIRM_TI5_TEST=YES \
  ./build/tools/ti5_zero_home --no-bring-up
```

菜单 1 和菜单 3 完成后保留 `mode=8` 和最后的 HOLD 目标；程序退出不会自动发送 STOP。需要取消双臂 CSP HOLD 时，重新运行并选择菜单 2。
