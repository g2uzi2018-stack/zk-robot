# TI5 T170C 整机实机测试

工程主程序 `robot` 是当前双臂、头部和灵巧手的组合联调入口。它直接使用
TI5 的 Arm、Head、Hand 及对应 Controller，不再包含单电机测试代码。

## 默认动作

1. 包含双手时，先配置手部适配器并确认左右手都能返回状态；
2. 发现左臂、右臂和头部的实际 CAN 接口；
3. 读取全部 17 个关节的位置、驱动器范围、运行模式和故障；
4. 从实测当前位置建立位置控制；
5. `left_wrist_roll` 向正方向移动 `0.01 rad` 后返回；
6. `right_wrist_roll` 向负方向移动 `0.01 rad` 后返回；
7. `neck_yaw` 向正方向移动 `0.01 rad` 后返回；
8. 核对全部关节返回起点；
9. 本体继续刷新起点目标，同时左手六个原始位置通道同步移动 `20` 后返回；
10. 本体继续保持，右手执行相同动作；
11. 默认请求、确认 Arm/Head 的 `mode=0`。

三个本体部件在同一个 `100 Hz` 循环中刷新目标。测试某一个部件时，另外
两个部件持续刷新自己的起始位置。手部按当前文档的状态查询参考周期独立、
依次测试，不与本体关节共用 CAN 接口。

使用 `--hold-after-test` 时，第 11 步改为：三个本体部件继续按 `100 Hz`
刷新起点目标，直到操作者按 `Ctrl+C`。灵巧手动作会在本体保持期间完成；
该选项不自动发送 STOP。

## 运行方式

只检查参数和配置，不打开 CAN：

```bash
./build/robot --dry-run
```

先只测试双臂和头部：

```bash
export ZK_ROBOT_CONFIRM_ALL_COMPONENT_TEST=YES
./build/robot --body-only
```

用更明显的 `0.05 rad` 位移测试，并在返回起点后持续保持：

```bash
export ZK_ROBOT_CONFIRM_ALL_COMPONENT_TEST=YES
./build/robot \
  --body-only \
  --hold-after-test \
  --arm-delta-rad 0.05 \
  --head-delta-rad 0.05
```

该命令使用了 `--body-only`，所以不进入手部测试。按 `Ctrl+C` 后程序停止
周期刷新并退出，仍不发送 STOP；驱动器保留最后目标和当前运行模式，但程序
退出后不能再称为主动刷新保持。

配置已经正式开放时，包含左右手：

```bash
export ZK_ROBOT_CONFIRM_ALL_COMPONENT_TEST=YES
./build/robot
```

在 `hands.yaml` 尚未正式开放前做受限首测：

```bash
export ZK_ROBOT_CONFIRM_ALL_COMPONENT_TEST=YES
export ZK_ROBOT_CONFIRM_UNVERIFIED_HAND_TEST=YES
./build/robot --commission-hands
```

执行双臂、头部和双手动作，并在全部动作完成后继续保持本体：

```bash
export ZK_ROBOT_CONFIRM_ALL_COMPONENT_TEST=YES
export ZK_ROBOT_CONFIRM_UNVERIFIED_HAND_TEST=YES
./build/robot \
  --commission-hands \
  --hold-after-test \
  --arm-delta-rad 0.05 \
  --head-delta-rad 0.05 \
  --hand-delta-raw 20 \
  --hand-speed-raw 5
```

首测选项只修改当前进程中的配置副本，不写回 `hands.yaml`。它仍要求终端
确认，并保留原始位移、速度、接口发现和反馈到达检查。

实际发送运动命令前还必须在终端输入 `y` 或 `Y`。程序会检查实机运动互斥
锁和已知控制进程，禁止与原厂控制程序或其他 zk_robot 实机工具并行运行。

可调整的测试量：

```text
--arm-delta-rad   0.001..0.40
--head-delta-rad  0.001..0.40
--hand-delta-raw  非零，绝对值不超过 50
--hand-speed-raw  1..20
```

手部参数是协议原始数值，不是弧度、毫米或百分比。

双臂和头部仍使用五次平滑曲线。位移较大时程序会自动延长单程时长，使规划
峰值速度不超过 `0.10 rad/s`；因此把位移设置为 `0.40 rad` 不会仍在固定
两秒内完成。

## 灵巧手控制门槛

当前已经实现傲意手的 `0x55 0xAA` 数据包、校验、CAN 分片与重组、控制器
ID 发现、`0x5F/0x80` 状态读取，以及 `0x50` 六通道位置和速度命令。尚未
确认的是独立停止命令、全部状态字段含义、左右手实际位置范围，以及通信异常
后的固件行为；因此当前仍保留首测门槛，不能把它描述成完整协议。

完整测试不会绕过 `hands.yaml`。左右手必须同时满足：

```yaml
protocol_verified: true
control:
  enabled: true
```

当前仓库仍为 `false`，因为左右实际接口、位置范围和异常行为尚未通过实机
确认。在这些字段被有依据地开放前，默认完整测试会在打开 CAN 之前拒绝；
`--body-only` 可以独立测试双臂和头部，`--commission-hands` 用于第一次受限
实机确认。首测成功后仍应根据实机记录判断是否正式修改配置，不能由程序
自动把 `protocol_verified` 写成 `true`。

## 异常行为

- 默认情况下，双臂或头部正常完成后，程序请求并确认 `0x02 STOP`；这不等于
  去使能，也不保证机械臂会继续承载，因此双臂必须全程有人可靠支撑。
- 使用 `--hold-after-test` 时持续刷新起点目标，不自动发送 STOP；收到
  `Ctrl+C` 后停止刷新并退出。
- 本体运动异常时，程序短暂刷新仍可控制部件的最后目标，不自动发送 STOP，
  避免把未经确认的释放行为当作保护动作。
- 灵巧手没有已确认的停止命令。手部异常时程序停止继续发送，但不能据此
  假定手已经停止、释放或断力。
