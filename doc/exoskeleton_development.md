# 外骨骼接入开发说明

本文档记录 Qnbot 外骨骼接入当前工程所需的协议、数据含义、现场标定结果和安全边界。
当前阶段只把官方读取器输出的编码器弧度值作为输入源，不把它直接当作已经完成机器人
关节坐标校准的目标角度。

## 1. 当前结论

- 官方读取器可靠地完成 legacy 遥测帧解析，以及有符号编码器计数到弧度的换算。
- 官方代码没有定义 `slot 0..7` 的人体关节名称、关节轴、零位偏置或左右臂语义。
- 当前工程的 C++ `exoskeleton_input` 已经独立实现相同的 legacy 解析，不依赖厂商 Python SDK。
- `tools/exoskeleton_joint_monitor.py` 是只读的项目内监视工具，直接读取已经输出的 legacy 流。
- 当前外骨骼读取层不会向 TI5 发送控制指令；向 TI5 的重定向属于单独的应用层映射。

官方读取器原始快照保存在 [doc/reference/remote_manipulator_data_reader.py](reference/remote_manipulator_data_reader.py)。
它是参考资料，不作为项目运行时依赖。快照来源为用户提供的官方文件，SHA-256 为：

```text
e61c685bb0db11bc6e7831731b76767965bfd652e968fa4108cd37e45704e0f3
```

## 2. Legacy 遥测协议

一帧数据的结构为：

```text
0xAA | payload | XOR | 0x55
```

其中 payload 长度可以是 48、88 或 128 字节，对应完整帧长度 51、91 或 131 字节。
校验值是 payload 所有字节的逐字节 XOR；整数采用 little-endian。

### 2.1 基础 payload（48 字节）

| payload 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0 | 8 | 左手柄：4 个 `int16`，X/Y/按键/扳机 |
| 8 | 8 | 右手柄：4 个 `int16`，X/Y/按键/扳机 |
| 16 | 16 | 左臂编码器：8 个有符号 `int16` |
| 32 | 16 | 右臂编码器：8 个有符号 `int16` |

### 2.2 IMU 扩展

88 字节 payload 在基础字段后增加 40 字节躯干 IMU：

```text
fAcc[3] | fGyro[3] | fQuat[4]
```

128 字节 payload 再增加 40 字节附加 IMU（当前代码按头部/附加 IMU 处理）：

```text
躯干 IMU 40 字节 | 附加 IMU 40 字节
```

因此日志中的 `format=3` 只表示同时包含躯干和附加 IMU，不表示存在 3D 人体姿态映射。

## 3. 编码器弧度换算

官方代码对左右两侧所有编码器使用同一个线性换算：

```text
encoder_rad = signed_raw_encoder * (2π / 16384)
```

这意味着：

- `arm_joint_left_rad[i]` 对应 `arm_joint_left[i]`；
- `arm_joint_right_rad[i]` 对应 `arm_joint_right[i]`；
- 编码器原始值增加时，SDK 输出的弧度值也增加；
- 代码没有额外的每通道取反、重排、零位偏置或齿轮比换算。

这里的“弧度”应理解为编码器读数换算后的弧度值。除非另有厂商标定资料，不能假定它已经是
TI5 模型坐标中的绝对关节角。

## 4. 槽位编号约定

本文使用 0-based `slot`，与官方数组下标一致：

```text
slot 0 = arm_joint_*[0]
slot 1 = arm_joint_*[1]
...
slot 7 = arm_joint_*[7]
```

项目监视器为了便于现场记录，将它显示为“关节 1”到“关节 8”，其中“关节 N”对应
`slot N-1`。官方文件只保证数组顺序，不给出人体关节名称。

## 5. 现场穿戴视角下的槽位和正方向记录

下面的正方向完全按照穿戴者自己的视角记录。表中的 `+1` 表示“编码器弧度增加时，
穿戴者观察到的运动方向”；它不是 TI5 目标模型的最终方向符号。

### 5.1 左臂

| SDK 关节编号 | SDK slot | 物理关节描述 | 穿戴者视角下的正方向 | 方向记录 |
|---:|---:|---|---|:---:|
| 1 | 0 | 肩部前后 | 向身体后方 | +1 |
| 2 | 1 | 肩部侧向 | 向身体内侧 | +1 |
| 3 | 2 | 上臂旋转 | 向身体外侧（逆时针） | +1 |
| 4 | 3 | 肘部前后 | 向上 | +1 |
| 5 | 4 | 肘部旋转 | 顺时针 | +1 |
| 6 | 5 | 腕部前后（末端第二个关节） | 向后 | +1 |
| 7 | 6 | 腕部左右（最末端关节） | 向身体中心（顺时针） | +1 |
| 8 | 7 | 尚未定义 | 当前日志为 0.0 | 未定 |

### 5.2 右臂

| SDK 关节编号 | SDK slot | 物理关节描述 | 穿戴者视角下的正方向 | 方向记录 |
|---:|---:|---|---|:---:|
| 1 | 0 | 肩部前后 | 向上（按原始记录保存） | +1 |
| 2 | 1 | 肩部侧向 | 向身体外侧 | +1 |
| 3 | 2 | 上臂旋转 | 向身体内侧（逆时针） | +1 |
| 4 | 3 | 肘部前后 | 向上 | +1 |
| 5 | 4 | 肘部旋转 | 顺时针、向身体外侧 | +1 |
| 6 | 5 | 腕部前后 | 向后 | +1 |
| 7 | 6 | 腕部左右（最末端关节） | 向身体外侧（顺时针） | +1 |
| 8 | 7 | 尚未定义 | 当前日志为 0.0 | 未定 |

右臂 `slot 0` 的原始描述同时写作“肩部先后/向上增加”，本文不替现场记录做解释性
修正；如果用于 TI5 重定向，应在目标关节接管前单独确认。

官方代码会解析 `slot 7`，但没有声明它是保留位。当前日志长期为 0 只能说明目前没有观察到
它的有效变化，不能据此完成语义确认。

## 6. 外骨骼到 TI5 的应用层映射

外骨骼输入进入 TI5 前，应该显式经过索引、方向和零偏映射：

```text
q_ti5[i] = scale[i] * q_exoskeleton_rad[source_slot[i]] + offset_rad[i]
```

其中：

- `source_slot[i]`：TI5 第 `i` 个目标关节使用的外骨骼槽位；
- `scale[i]`：目标模型正方向与外骨骼记录方向不一致时取 `-1`，否则取 `+1`；
- `offset_rad[i]`：外骨骼中性姿态到 TI5 模型零位的偏置。

不能把本表中的现场方向记录直接当成 TI5 的 `scale`。TI5 自身的模型方向和电机方向，
参见 [doc/ti5_motor_direction_record.md](ti5_motor_direction_record.md) 以及
[config/ti5/t170c/kinematics.yaml](../config/ti5/t170c/kinematics.yaml)。

当前建议的接入顺序：

1. 只读读取并记录左右 `slot 0..7` 的弧度值。
2. 确认目标机器人 7 个关节的顺序、方向和零位。
3. 填写 `source_slot/scale/offset_rad`，先以仿真或目标位置打印验证。
4. 做初始姿态接管和限位检查。
5. 最后才允许向实体 TI5 发送目标。

## 7. 当前项目工具

### 7.1 只读 Python 监视器

该工具不加载厂商 SDK，只使用 `pyserial` 读取已经存在的 legacy 流：

```bash
python3 tools/exoskeleton_joint_monitor.py --port /dev/ttyACM0
```

它会固定显示左右两侧的“关节 1”到“关节 8”，只刷新 `raw` 和 `rad` 数值，不刷新静态
标签，适合现场逐轴动作记录。它不会打开 TI5 CAN，也不会向外骨骼发送 QnTP 或控制命令。

### 7.2 C++ 输入和监视器

`src/input/exoskeleton/` 是项目内的实时输入层，包含串口重连、帧同步、校验、格式 1/2/3
解析和状态新鲜度判断。`exoskeleton_monitor` 只读打开外骨骼，不控制机器人。

### 7.3 串口占用

同一时刻只能有一个程序独占 `/dev/ttyACM0`。运行 Python 监视器、C++ 监视器或后续
遥操作程序前，应先退出其它串口工具。

## 8. 官方资料的保留范围

项目保留官方 `remote_manipulator_data_reader.py` 的原始快照，用于核对帧结构和弧度公式。
原来的完整 Python SDK 快照、CLI、GUI 演示、DFU 和其它与当前 legacy 只读接入无关的工具不
参与项目运行，也不作为当前控制层依赖。

如果后续确实需要 QnTP 设备配置、手柄校准、Wireless、Haptics、DFU 或厂商 3D 工具，
应从厂商获取对应版本的独立资料，不要把这些未验证功能混入实时机器人控制周期。
